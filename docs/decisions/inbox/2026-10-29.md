### 464. [mimic-app] Code signing re-opened 2026-10-29: Azure Artifact Signing pipeline landed, off until the six settings exist; SignPath re-application offered
The guild lead, after a VirusTotal report on the installer: *"we should try to get resigned"*. Code signing had been closed on
2026-07-14 (SignPath declined: user base too small).
- **Landed on main (docs + CI only, no Mimic version change, so no release):** `apps/mimic/scripts/azure-sign.cjs` as
  electron-builder's `win.sign` hook (SignTool + the Artifact Signing dlib), and `release-mimic.yml` steps that detect the
  settings, install the signing tools, verify the signature (`Get-AuthenticodeSignature`) and the manifest hash, and word the
  release body by whether signing ran. Tests: `test/codesign-wiring.test.js`.
- **Off until all six settings exist:** secrets `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`; variables
  `AZURE_SIGNING_ENDPOINT`, `AZURE_SIGNING_ACCOUNT`, `AZURE_CERT_PROFILE`. With none set every build is the unsigned build it
  always was; with all six set an unsigned result fails the build (fails closed). Partial settings count as unset.
- **Why Azure:** a CA-issued certificate the guild lead's identity validates, billed monthly, no hardware token, and it works
  from GitHub-hosted runners. A SignPath re-application (open-source tier) was drafted as the fallback; not sent.
- Setup steps for the guild lead: `docs/code-signing.md` "Turning it on".
