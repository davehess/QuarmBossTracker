### 474. [web] Guest Mimic links: an officer-approved, time-limited key that uploads parses only (bot 4.0.35 + web 2.1.70, first draft, 2026-10-30)
The guild lead: *"where can i give someone a temp key to contribute to shared parses as a raider from another guild"*, and picked the
officer-approved guest link (option A) over a self-serve code.
1. **Flow.** The guest opens Mimic and signs in; Mimic shows a short code; an officer enters it on https://wolfpack.quest/admin/links
   ("Guest links") with a label ("character of guild", required, 64 characters) and an expiry: **1 hour**, **3 hours**, **Tonight (until 1 AM Eastern)** or **7 days**. (Same day, the guild lead: "needs a
   shorter timeframe too, like 1 hour, 3 hours" and "why 6am eastern?": the draft's "Tonight" ran to 6 AM; it now ends at 1 AM,
   half an hour past the raid window.)
   Same code checks as the member link (unknown, expired, already used). Every approval and every revoke is an `audit_log` row.
2. **A guest is not a member.** The session carries `scope = 'guest'`, an `expires_at`, the label, and a synthetic id `guest:<session id>` in
   place of a Discord id (it lands in the `uploaded_by_discord_id` text columns, so a guest's contributions are findable by the prefix). It has no
   roles, is never an officer, and is not in `wolfpack_members`.
3. **What a guest may call**: `POST /api/agent/encounter` (the parse upload), `GET /api/agent/poll` (answered with no streams, only the kill
   switch and version floor, so the guest's agent does not retry a refusal every 1.5 s), and the unauthenticated `GET /api/agent/latest-version`.
   Every other route answers `403 {"error":"guest_scope"}` from `requireAgentAuth`, before the handler runs: one allowlist, not one per handler.
   The agent drops a 4xx upload as permanent and polls on its own cadence, so nothing spins; the refusal is logged once per guest per route.
4. **What a guest upload does**: the parse is recorded and merged into the shared encounter like any raider's. It is treated like a log replay
   for everything live: no Discord parse card, no session totals, no boss auto-kill or timer, no live raid-review count. It writes no /who data,
   no `/parseagents` activity, no raider deaths, and no upload-stats row (those count players, and a guest is not one).
5. **Ends.** Expiry answers 401 like a revoked session (never cached past it); a Revoke reaches the bot within a minute (guest identities are cached
   for 60 s, not 5 minutes).
6. **Open.** (a) The migration `20261030150000_mimic_guest_sessions.sql` must be applied BEFORE the bot deploys. (b) A guest's parse does not get
   a card in the raid thread; say so if the guild lead wants one marked "guest". (c) Whether a guest's character should appear on the website
   (the encounter merge writes `encounter_players` by name; no `characters` row is created by this path).

### 489. [process] Supply chain: no new runtime library for the UI work, and every tool or MCP is pinned, read and run in the cloud first (2026-10-31)
The guild lead, on the UI tooling list: *"we should be concerned with any of these libraries being poisoned."* The rules:
1. **Pick C already adds no dependency** (§488): no daisyUI, no design toolkit plugin. The three token layers are our own CSS.
2. **An MCP server runs with the session's own tool access**, so it is code we execute with our credentials. Only one is
   considered, Google's `chrome-devtools-mcp` (an organisation publisher, Apache-2.0): pinned to an exact version in
   `.mcp.json` (never `npx -y …@latest`), its source read at that tag before it is added, telemetry off
   (`--no-usage-statistics`), run in the cloud container against the stand-in overlay server first and on the guild lead's PC
   only after that. Individual-author Electron MCPs (`electron-mcp-server`, `electron-mcp`, and the blog-post ones) are not
   adopted: one ships an `eval` tool its own README says is blocked.
3. **A Claude Code plugin or skill is prompt text that steers every session**; a third-party one is vendored only after it is
   read in full, as impeccable and ponytail were (CLAUDE.md, the two vendored skills). The Gemini-suggested toolkit is not.
4. **For anything that reaches a member's PC** (Mimic's own dependencies), the standing rule stays: the agent has zero npm
   dependencies; Mimic's are pinned and the lockfile is the record; nothing from an MCP or a design tool ships in the app.
5. **Checked 2026-10-31.** `chrome-devtools-mcp@1.12.0` (2026-10-22): publisher Google LLC, npm provenance + SLSA attestation,
   zero runtime dependencies (bundled), no install scripts on a registry install, two past advisories (CVE-2026-53765/53766, fixed
   in 1.1.0). Telemetry is ON by default: run with `--no-usage-statistics --no-performance-crux` and
   `CHROME_DEVTOOLS_MCP_NO_UPDATE_CHECKS=1`, after which its only traffic is loopback CDP. The others: holepunchto's fork is
   unpublished (build from source, adds only port scanning and a Puppeteer patch); `electron-mcp-server` (individual, 166
   transitive deps, Electron postinstall, an eval tool at its permissive level) and `@kanishka-namdeo/electron-mcp-server`
   (individual, no attestation, 112 deps) are skipped; the "design toolkit" is a README of links, not code; Figma does not apply.
   Electron acrylic/mica (`setBackgroundMaterial`, Windows 11 22H2+) draws a system backdrop over the whole window rectangle and
   is unproven with `transparent` + click-through: skipped for overlays.

### 490. [infra-costs] Bots at scale: hybrid (shared commons bot + a dedicated bot per paying guild), no service_role for guild data, wildcard subdomains (`DESIGN-raidmimic-hosted.md` §9, 2026-10-31)
The guild lead asked what one bot per guild versus generic load-balanced bots would cost and whether a shared bot is "an easy
way for data to be exfiltrated programmatically". Measured: one guild's bot is $1.20/mo of Railway usage (0.08 GB, 0.02 vCPU on
average). §9 recommends **C, hybrid**: the commons and guests on one shared bot, each paying guild on its own process with its own

the guild set from the session token, so a missed filter returns nothing. Subdomains are a Vercel wildcard on `*.raidmimic.com`
(Pro plan, nameservers at Vercel). Guest parses live under the approving guild's `guild_id`. Cost per guild falls from ~$7 at 10
guilds to ~$2.50 at 100. Other games need a `game` key and a parser module per game; live EQ is the cheapest second target.
