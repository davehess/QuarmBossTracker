### 533. [mimic-app] A Windows 7 build of Mimic: Electron 22, the agent on Node 16 with a shim, its own rolling release (Mimic beta `a26291bf`, 2026-11-04)
The guild lead, for a member on Windows 7 who needs the charm tracker: *"Try a release on Electron 23 and Node 14 for him as a
beta release for Windows 7 specifically. He needs the charm stuff"*.
- **Electron 22.3.27, not 23.** Electron 23 is the release that dropped Windows 7, 8 and 8.1, so 22 is the newest that
  starts there. Its Node is 16.17, and Node 14 is not an option inside it. The agent runs under that Node
  (ELECTRON_RUN_AS_NODE).
- **`apps/mimic/node16-shim.js`** gives the agent the two Node 18 things it uses: a global `fetch` (ok, status,
  headers.get, json, text) and `AbortSignal.timeout`. main.js copies it to userData and passes `--require` ahead of the
  agent only when its Node is older than 18, so every normal build gets no extra arguments. Agent 4.0.60 parses, boots and
  serves its dashboard on Node 16.17.1 with it; Mimic's own code already had fallbacks for its two newer Electron calls.
- **Its own update track.** An Electron < 23 build reads only the rolling prerelease tagged `mimic-win7` (`win7.yml`, read
  from its fixed address like the alpha), ignores every channel toggle, and can never take a normal Electron 31 update.
  Version `<beta version>-win7.<run>`.
- **It follows beta.** `.github/workflows/build-mimic-win7.yml` runs on every beta push touching Mimic or the agent (and by
  hand), pins Electron 22 for that job only, fails if the result is not Electron 22, and replaces the rolling release's
  files. Unsigned, like every Mimic build.
- **Known risk:** the agent hot-swaps along the beta line. If a future agent uses a Node 18-only API the shim does not cover,
  the Windows 7 agent fails to start and Mimic's last-known-good rollback takes it back. The shim's header is where to add
  the next missing piece.
- Untested on a real Windows 7 machine: the member is the test.
