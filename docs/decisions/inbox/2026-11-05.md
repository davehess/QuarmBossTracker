### 539. [infra-costs] Fight snapshots move to Supabase Storage, one file per fight, kept forever (bot 4.0.56, 2026-11-05)
The guild lead, after the 2026-11-04 Disk IO outage (§538): *"do A, keep everything"*, then *"A, ship it switched off and apply the
migration"*.
- **Where:** Supabase Storage (A), not Cloudflare R2 (B): $0 on Pro (100 GB of storage included), no new account or keys, and it
  does no database disk work. R2 stays a one-day swap if download fees ever matter (free reads); a whole-stack move (Cloudflare
  Pages, Neon, Clerk, Resend) was weighed the same night and declined: the database is also our sign-in, access rules and file
  store, so a move costs weeks and every member's sign-in for little gain. The one layer worth revisiting is the website host:
  Vercel's free plan is non-commercial, so a paid host (Vercel Pro or Cloudflare Pages) comes before the first paying guild.
- **What:** the bot holds a fight's snapshots in memory and, 5 minutes after the fight's last snapshot, writes one gzipped file to
  the private bucket `fight-snapshots`, indexed in `fight_snapshot_files` (migration `20261105120000`, applied 2026-11-05 06:46 UTC).
  **Kept forever.** Live readers (Mimic's "synced" guild numbers) answer from memory; threat ranks are upserted per fight.
- **Staged by a switch, because the bot has no beta:** tuning number `snapshot_store`: 0 rows only (shipped default), 1 rows AND
  files (one raid night, to compare), 2 files only (removes ~15k raid-night writes and the table's growth).
- **Before 2:** the parse page's damage curve and the raid session's fight timeline read per-fight graphs that
  `build_encounter_threat_graphs` builds nightly from the rows, so mode 2 must build each fight's graph when its file is written;
  trash ranks also merge approximately in mode 2. Mode 1 is safe as is.
- **Correction for the record:** "no website page reads the snapshots" (said in chat that night) was wrong; those two pages read
  them through the stored graphs.
- **Mode 1 switched on 2026-11-05 20:55 UTC** (the guild lead: *"set mode 1. we have a raid tonight hitting plane of water and
  potentially plane of air … see what we pull back and then if it works out we can look into … mode two for Sunday"*). Set in
  `overlay_tuning.tuning.snapshot_store` (no deploy; live within the 60 s tuning cache). After the raid: compare each fight's
  file against its rows; mode 2 for Sunday only once the per-fight graph is built at file write.
