### 563. [mimic-app] Bring your setup to this computer: what it brings, what it protects, where it lives (the guild lead, 2026-11-11)
A member came to play on the guild lead's PC, signed in to Mimic as himself, and his cloud backups never came down: Mimic
only offered backups for characters it found on that PC's disk. His chat windows also came up off the 1080 screen.
*"we need a way to ask the user if they want their config on this machine if it's not already there, and collapse other
characters into an unshown section. the backup import should ask to bring in everything"*, then *"add overlay positions to
the backups too, and backup the eqclient.ini before doing any of those actions. let him pick from a list which characters he
wants and check them at the top level to pull them in. if multiple machines exist show them in most recent order. we should
keep the last few backups for character files automatically when changes happen"*, and *"getting started is good but it
should be front and center AND clear to use in UI studio"*.
- **Bring-in:** one card (`apps/mimic/bring-setup.js`) in the setup walkthrough (a step right after sign-in), UI Studio's
  top bar and Settings. A top-level checkbox per character of the signed-in account; each expands to its backups grouped by
  computer, most recent computer first. Bot route `GET /api/agent/ui_layout/characters` (bot 4.0.77) lists them without a
  character name. Mimic beta `697ca2cd`.
- **Everything comes in:** layout and chats (fitted to this screen, off-screen windows pulled back on), hotbuttons, socials,
  spell sets, bandolier and the other character files, and Mimic overlay positions (new in the backups).
- **The host is protected (a session's default, kept):** on a PC that also holds another account's characters, key
  bindings and Zeal settings start unticked, because `eqclient.ini [KeyMaps]` and Zeal's shared sections apply to every
  character there. A dated copy of `eqclient.ini` and `zeal.ini` is saved before any restore writes (newest 10 kept).
- **Versions:** the after-camp cloud backup is on by default and uploads only on change (bot keeps 5 per character and
  PC); the last 5 versions of each character's files are also kept on the PC, listed as "On this computer".
- **Not done:** making the walkthrough the default first-run page. `loading.html` also boots the agent and owns the
  first-run EQ-folder card and the first navigation, so the switch is a handover design, not a one-line change.
- **Later, a pick:** whether a shared PC should keep key bindings and video settings per account and swap them on sign-in.

### 564. [zeal] Zeal opt-in: a character's own settings in a file of their own; UI Studio lists every change (the guild lead, 2026-11-11)
*"let's make a Zeal fork that includes an opt-in to separate character specific settings into character specific files so
that they can be updated after a character camps. we should always retain previous and show [a diff] to previous ... and
then list all of the changes not just the ones that we've [made] in the UI studio."*
- **Zeal (fork, `feat/char-settings-files` b4ead23 on v1.5.0-alpha0):** `/zeal charfile on|off` (zeal.ini `[Zeal]
  CharacterSettingsFile`, default off). When on, every per-character `ZealSetting` (about 72; one choke point in
  `zeal_settings.cpp`) is read from `<Name>_zeal.ini` first, falling back to the old `[<Section>_<Name>]` sections in
  zeal.ini, and written only to the new file; the first use copies the old values over and leaves them in place. Zeal keeps
  nothing per character in eqclient.ini (checked), and its extra chat channels were already in the UI file. Compiled by the
  fork's `test-charfile` build (release `test-charfile-build`, label `charfile-54e870e`); NOT in `wolfpack/approved.txt`
  until the guild lead has run it in game.
- **Mimic needs no change for it:** `<Name>_zeal.ini` is named for the character, so it is in the backup bundle and a
  restore writes it with the character's own files, at camp.
- **UI Studio (Mimic beta `d5b78fa2`):** every Mimic write saves the files first (10 kept, each labelled game / ui-studio /
  restore / layout); a Changes view lists every key changed since a chosen version, labelled UI Studio or in game, with a
  toggle to hide UI Studio's own (default off: everything is listed).
