# Zeal `/tag` spawn-id capture — raid night 2026-08-06

Snapshot pulled live at 23:1x ET from `character_live_state.zeal_tags`, which is
overwritten every few seconds and has **no durable table**. Kept here because it
is the first field evidence that the `/tag` chat channel delivers the one datum
the Zeal named pipe does not: a **spawn id**.

## Why this matters

`CLAUDE.md` (Scope boundaries) states, correctly for the *pipe*:

> ≥2 identically-named mobs alive at once can't be told apart from the pipe …
> Do NOT design features that need N≥3 simultaneous same-name identities — the
> data can't support it.

The pipe still can't. **The tag channel can, for tagged mobs.** Tonight caught
three simultaneous `protector of Zek` resolved to distinct ids (148 / 149 / 150),
plus two `an aged caretaker` (57 / 61) and two `an ancient sentry` (39 / 45).
That is exactly the N≥3 case, disambiguated.

The constraint is now **coverage, not capability**: a mob is only identifiable if
somebody tagged it. Three raiders tagged all night — Dafeet, Canniball, Jankzer.

## Gap this exposes

`zeal_tags` is a jsonb column on the live-state row, replaced on every upload.
Nothing writes tag history anywhere. Tonight's Rallos Zek tags were already gone
from the live rows by 23:13 — this file is the only copy. If tag-derived
identity is going to be load-bearing (same-name split, threat attribution), it
needs a durable table keyed `(zone, spawn_id, first_seen)`.
